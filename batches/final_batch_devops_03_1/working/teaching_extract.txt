f2: Call aws sts assume-role with --role-arn, --role-session-name and the approved --duration-seconds, then use all three returned credential fields and inspect Expiration.

tb4 [f1,f2,f3]: Substitute the approved role ARN, session name and duration in the assume-role command. Use the returned access key ID, secret access key and session token together, and inspect Expiration. If a session policy is supplied, role identity-policy permissions are intersected with it. An applicable explicit deny still overrides an allow. Record the issued lifetime and the supplied permission evidence without displaying credential values. This example teaches session composition and the stated grant distinctions, not a new policy intended to exercise every possible permission case.
tb5 [f1,f3]: Temporary credentials are not just an access-key pair: the session token is also required, and the issued lifetime ends. Likewise, session-policy intersection describes role identity-based grants; it is not an unqualified limit on all resource-based grants.

tb4 [f1,f2,f3]: For a supplied target that requires an execution role, grant events.amazonaws.com the approved trust to assume it and scope role permissions to the approved operation and resource. For a supplied SNS or Lambda target, use the required resource-based invocation permissions instead. Compare the selected target with its authorization model in the record. The selection pattern determines which events match; the separate authority determines whether the intended target operation is permitted. Do not assign a role to every target just because a different target used one.

Trust permits EventBridge to assume the role; the role's permissions cover the approved target action. For the SNS or Lambda case, inspect the resource-based invocation permission instead. These are different authorization records even if the same event pattern selects the event, which is why matching alone cannot verify target execution authority.
tb5 [f1,f3]: Event selection and execution permission are separate. SNS and Lambda use resource-based invocation permissions in this brief, so assuming every target uses an execution role misstates the authorization model.
