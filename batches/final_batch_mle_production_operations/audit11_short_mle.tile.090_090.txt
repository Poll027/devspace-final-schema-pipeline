Use the nonproduction runbook and authorized recovery identity; reproduce and isolate the injected service fault and test one recovery hypothesis before the lifecycle action. Inspect instance status/identity and process/service state, recording fault evidence before recovery. Perform the runbook-approved gcloud compute instances stop INSTANCE --zone=ZONE, wait for completion, then start the same authorized instance and wait until it is running.
Reconnect with gcloud compute ssh INSTANCE --zone=ZONE and inspect the restored process/model service state. Verify model readiness and a bounded prediction exchange after restart, comparing the restored service behavior with the expected contract. Use existing runtime-injected credentials without embedding them in recovery code/configuration or printing them in captured output.
Inspect with gcloud compute instances describe INSTANCE --zone=ZONE: the instance status and identity before and after the authorized lifecycle action.

mle.tile.090_090.s02 Apply the rule: Use an ML incident runbook for safe recovery on an existing platform

Reconnect and inspect the model service. Check readiness and a bounded prediction exchange against the contract; a running VM is not sufficient. Describe identity/state before and after. Keep runtime credentials out of commands, configuration and captured output.
