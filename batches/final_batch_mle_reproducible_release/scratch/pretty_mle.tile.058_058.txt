
mle.tile.058_058.s01 explainer Freeze before protected testing
Fix candidate, fitted preprocessing and threshold before protected testing. Report disappointment; do not let test outcomes choose a replacement.
After freezing the selected candidate, preprocessing and threshold, predict the same protected observations with candidate and baseline. Compare precommitted predictive quantities on that cohort. Test results must not select a new candidate or threshold. Use fixed deployment probabilities, error costs and operating requirements; report failure rather than retuning.
For binary counts, FPR = FP/(FP+TN) conditions on actual negatives; FNR = FN/(FN+TP) conditions on actual positives. An empty conditioning group has no defined rate. With zero cost for correct predictions and supplied deployment probabilities, expected error cost = P(Y=0) × FPR × cost_FP + P(Y=1) × FNR × cost_FN.

mle.tile.058_058.s02 explainer Report the frozen comparison, even when it fails
Validation selected B and its threshold. Use B and baseline on the same protected orders, even if this cohort’s observed class mix differs. Keep fixed deployment probabilities and costs instead of changing inputs to make B pass. Retain actual-class conditioning counts and check precommitted quality and operating requirements. Report B’s failure. Adjusting the threshold from these outcomes would let protected observations select the system: this is a final matched comparison, not another selection round.
Freeze choices before observing outcomes: model identity, fitted preprocessing, threshold, metric inputs and requirements. Observed test conditioning counts and supplied deployment probabilities have different roles; retain both. Explicitly report undefined required quantities or failed requirements, without turning final testing into more tuning.
Protected testing is not another tuning round. Failure does not authorize switching candidate, refitting preprocessing or searching for a better threshold on those observations.
