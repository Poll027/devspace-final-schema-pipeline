mle.sensitive_ml_assets
tb1 An inspection record contains useful diagnostics and a credential. The dataset or log being readable does not grant permission to redistribute every field. Apply the existing identity and permitted-field policy before creating a new record.
tb2 Data access is governed by authenticated identities and authorization, not merely by possession of a dataset or log file. Implement the supplied permitted-field policy with dictionary membership checks and create a record containing only the permitted values. Credentials written into an image or its metadata can be exposed; remove literal credentials from the data/log sample rather than treating them as ordinary diagnostic values.
tb3 Keep the credential value in the authorized runtime secret mechanism rather than copying it into a generated record.
tb4 Suppose the supplied policy permits run_id and row_count, but not token or raw customer values. Construct a dictionary containing the permitted fields using membership checks; the new record should contain the run identifier and count without the credential. Keep the credential in the authorized runtime secret mechanism, not in an image, metadata or diagnostic record. Test a sample containing both permitted and forbidden keys and inspect the resulting record rather than assuming a field was removed. This is implementation of an existing policy, not permission to invent new readers or expand the permitted field list. A useful error report can identify the handling problem without reproducing the literal credential.

Build a new permitted-field dictionary rather than copying the whole input and hoping no forbidden field remains. The membership rule should use the existing allowed-field collection; adding a field because it appears diagnostically useful would change policy. Inspect both the returned dictionary and the captured output. A removed token field in the returned record does not establish non-disclosure if the input was printed beforehand. Runtime credential delivery and diagnostic-field selection address related but distinct handling paths. Keep the credential reference usable by the permitted runtime while keeping its literal value absent from generated data, metadata, images and logs.
tb5 Possession of a file is not authorization to expose its contents. Moving a literal credential from a data sample into image metadata or a generated diagnostic record does not remove the exposure risk.
