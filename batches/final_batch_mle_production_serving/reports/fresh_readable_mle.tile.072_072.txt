mle.tile.072_072.s02 Verify replacement endpoints before retiring the faulty release
After replacement readiness and a verified JSON prediction/version response, stop and remove only the faulty test release, preserving the approved replacement.
Send a JSON request body as encoded bytes in urllib.request.Request(url, data=body, headers={"Content-Type": "application/json"}, method="POST"), then read the response through urlopen with a stated timeout.
Serialize structured request/response values with json.dumps; decode JSON with json.loads before inspecting fields.
Inspect the running container identity and State, including Health when a healthcheck is configured, and compare them with the intended release.
Inspect runtime logs for initialization and execution failures without copying sensitive request data or credentials into the evidence record.
Call the declared readiness and prediction endpoints with bounded timeouts and check the returned status and payload against the expected contracts.

mle.tile.072_072.s03 Trace the approved rollback replacement
Keep the faulty test release running while starting the approved previous release under its distinct identity and published port. Resolve the recorded immutable artifact rather than latest. Inspect replacement State, available Health and sanitized logs. With bounded calls, verify readiness and decoded JSON prediction/version against the contract. Only then stop and remove the faulty test release, preserving the replacement. Keep credentials runtime-injected, not in image metadata, Compose values or evidence.
Rollback is not ‘use latest’ or remove everything old. The target must retain its approval/version identity, and the faulty test release is not retired before replacement readiness.
