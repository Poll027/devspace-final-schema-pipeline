
### python.datetime_operations
A report needs the signed number of days between two calendar dates. Parse the supplied text with an explicit format before subtracting the date values.
datetime.strptime(text, format) parses text according to an explicit format, and .date() obtains its calendar date.
Use %Y-%m-%d for a year-month-day numeric date. Subtracting one date from another returns a timedelta representing their difference. For calendar dates, (later_date - earlier_date).days gives their signed day difference.
Separate parsing from date arithmetic:
```python
from datetime import datetime
first = datetime.strptime("2025-03-01", "%Y-%m-%d").date()
second = datetime.strptime("2025-03-04", "%Y-%m-%d").date()
print((second - first).days)
print((first - second).days)
```
The outputs are 3 and -3. Strptime uses the year-month-day format, and date() obtains the calendar date. Subtraction returns a timedelta, whose days gives this signed calendar-date difference. Check which date is later and which subtraction the requirement asks for before interpreting the sign.
The difference is signed, not always an absolute distance. Reversing the order of subtraction reverses the sign in this calendar-date example.

### python.logging
A command program needs progress messages and diagnostics with different importance. Logging names the source and assigns a level to each event.
After import logging, logger = logging.getLogger(__name__) obtains a logger named for the module.
DEBUG is for detailed diagnostics, INFO for expected progress, WARNING for an unexpected condition while operation continues, ERROR for inability to perform a function, and CRITICAL for a serious failure. Emit events with logger.debug(message) or logger.info(message), choosing a method corresponding to the desired level. Configure application logging with logging.basicConfig(level=logging.INFO) to include INFO and higher events; the default root threshold is WARNING. Propagation normally passes events to ancestor handlers; attaching handlers to both a logger and its ancestors can duplicate output, so ordinarily configure a handler at one suitable ancestor.
Configure an application and emit events:
```python
import logging
logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)
logger.debug("Detailed quantity calculation")
logger.info("Report complete")
```
INFO and higher events are included under this configuration, while DEBUG is below the threshold. Without that changed root threshold, the default is WARNING. Use WARNING for an unexpected condition while continuing, ERROR for inability to perform a function and CRITICAL for serious failure. Normally configure a handler at one suitable ancestor rather than both a logger and its ancestors, because propagation can otherwise duplicate output.
