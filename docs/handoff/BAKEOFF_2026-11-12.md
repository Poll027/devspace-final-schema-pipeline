# Model bake-off for the Final Schema pipeline (2026-11-11 to 11-12)

Goal: find a generator and evaluator that cost far less than Claude on Bedrock (Data Analyst final schema: $965.74, about $13 per tile) while passing the same gates. Everything ran on Azure (GPT-6 and DeepSeek on Foundry), Flex tier where the model offers it.

Cheap DeepSeek models are not usable as evaluators. GPT-6 evaluators are stricter than the Claude evaluators that gated Data Analyst.

Sol's tiles match Claude's structurally (same steps and interactions, 92 to 97 percent of the words, more remediation steps). A cheaper generator (Terra) cost more overall because it needed more repair and evaluation rounds. Evaluation is about 60 percent of the cost. DeepSeek V4.1 Flash completed no batch (it wrote tests expecting 12 rows for an 8-row file and did not repair it).
Caveat: 3 easy-to-medium Python tiles; chart and spreadsheet tiles did not complete, so do not extrapolate blindly.

## Pipeline defects found and fixed (all on main)
- `0428768` MAX_ROUNDS and MAX_STALLS env limits (defaults unchanged); a deployment with no Flex tier (gpt-6.1-terra) is retried without it.
- `35fbb60` Spreadsheet practices have no `live_code` list in the glossary, so generators left `allowed_syntax` empty and the gate called every operator "not yet taught" (misleading message, 5 wasted repair rounds). The gate now says what is wrong and the generator instruction says to derive the list.
- `191f2c3` The 04 evaluator proposed fixes that break the tile plan ("replace the formula_entry with a choice", "add a check after s11"); the generator may not do that, so batches looped on one blocker. The evaluator now fixes inside the plan or reports `PLAN GAP:`. This unblocked both Python batches.
- `ebc9e9a` `validate_tile.py` iterated sets when emitting warnings, so `reports/validation.tiles.json` had a different hash per process (old code: 7 distinct hashes over 8 hash seeds) and the ledger randomly called 07_validate STALE. Fixed with `sorted()`. The final audit also now runs `selftest.py` on the canary baseline (13 mutations, 0 missed), never on the batch under audit.

## Open
- **Chart tiles (VIZ) fail for every model** at stage 03: the evaluator wants rendered plots, the generator instructions say "no image assets exist", and Claude's gold tiles needed hand-written render scripts. Needs a deterministic render-to-asset step. Likely needed for ML plots too.
- **Spreadsheets**: `formula_entry` grading cannot validate the typed formula's arguments (evaluators ask for it), and the plan forces `formula_entry` on UI-only practices (sorting, filtering). Matters only for Data Analyst.
- Not tested: tiles with many interactions, SQL, the full 63-path mix, DeepSeek or Kimi as repair-only models.
- The AWS DevOps and ML TOC runs are paused (both about 400+ concepts; scope decision pending).
- The VM is deallocated; idle time while waiting cost real money, so deallocate when a run ends.
