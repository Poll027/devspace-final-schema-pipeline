# 03 screens — EVALUATOR
Fresh context. Re-derive from the glossary facts/blocks and registry; do not check the generator against itself. Run no scripts the gate already ran (assemble + validate passed).

BLOCKING: text states something the facts don't support, or changes a fact's meaning/hedge; a required fact is missing or only implied; the learner needs a `blocked_future_concepts` idea to understand a step; an example contradicts the registry data; text that only makes sense with the video; a visual that misleads or cannot serve its `visual_anchor.purpose`; remediation that teaches something false. ADVISORY: wording, length, tone, example choice, repetition.
Open the glossary `source_refs` only for facts you doubt. Review every step of the canary tile; later chunks: at least a third of steps (no more than about two thirds).
`annotated_image` blocks: the picture is a rendered plot registered in stage 01; judge it from the packet's `[IMAGE ...]` line (title, `alt_text`) and the plot code shown with it. BLOCKING: the step's text claims something the plot code does not produce; the two images of a before/after differ in anything but the taught change; `alt_text` copied wrongly. Do not demand an image that is not registered, and do not ask for a different rendering.
End with `VERDICT: PASS|FAIL`, then one line per defect with pinned replacement wording for every blocker: `BLOCKING|ADVISORY <step_id>: problem → exact fix`.
